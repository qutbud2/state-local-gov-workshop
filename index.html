1. Workshop Overview & Objectives

This workshop walks state and local government teams through designing a shared data ontology across agency systems, then using Rayfin to stand up a conversational data agent that department staff, analysts, and the public can query in plain language.

By the end of this workshop, participants will be able to:

  • Identify and catalog the core data sources used across government departments
  • Design an ontology that models citizens, services, cases, assets, and finances as connected entities
  • Build and configure a Rayfin data agent on top of that ontology
  • Test the agent with realistic constituent and staff questions
  • Identify at least ten applications they could build on this foundation

Audience: IT/data teams, GIS analysts, 311/constituent services leads, budget and finance staff, and digital services teams within city, county, or state government.

2. Prerequisites & Setup

  • Access to a Rayfin workspace with permissions to create data agents and ontologies
  • Read access to at least two or three source systems (e.g., 311/CRM, permitting, financial/ERP, GIS, CAD/RMS)
  • A data governance contact who can confirm which fields are public, internal-only, or restricted (e.g., CJIS, HIPAA, PII)
  • Sample or production datasets for the exercises in Module 4
Note: Government data often mixes public records with legally restricted data (criminal justice, health, tax). Confirm classification and access rules before connecting any source.

The ontology is the shared "map" that lets the data agent reason across siloed systems. Below is a starter ontology for state and local government.

6. Module 3: Building the Data Agent in Rayfin

  1. Connect sources: Register each system (311/CRM, permitting, financial, GIS, CAD) as a data source in Rayfin.
  2. Map to the ontology: Link source tables/fields to the entities and attributes defined in Module 2.
  3. Define relationships: Configure joins (e.g., Service Request to Department, Permit to Property) so the agent can traverse connected data.
  4. Set agent instructions: Give the agent context on terminology, units, jurisdiction boundaries, and which data is public vs. restricted.
  5. Apply access controls: Restrict sensitive entities (e.g., case details, CJIS data) to authorized roles only.
  6. Test and refine: Run sample questions, review the agent's reasoning and sources, and adjust mappings or instructions as needed.

7. Module 4: Hands-On Lab

Using your connected ontology, try these sample questions with your Rayfin agent:

  • "How many open pothole requests are there in District 3 this month?"
  • "Which permits for 123 Main St are still pending inspection?"
  • "What is the average response time for fire incidents in the downtown zone?"
  • "How much of the Parks Department's FY25 budget has been spent so far?"
  • "List all code enforcement cases older than 90 days assigned to inspector Garcia."

Exercise: Write three questions specific to your department's data and verify the agent answers them correctly and cites the right source records.

8. Module 5: Applications You Can Build With Rayfin

Once your ontology and data agent are in place, they become the foundation for many citizen-facing and internal applications. Here are twelve examples:

1311 Citizen Service Chatbot

Users: Residents
Lets residents submit and track service requests in natural language instead of navigating a form.
"Where's my pothole request from last week?"

2Permit & Licensing Assistant

Users: Residents, businesses
Guides applicants through permit requirements, fees, and status without calling the office.
"What permits do I need to open a food truck?"

3Code Enforcement Dashboard

Users: Inspectors, supervisors
Cross-references properties, violations, and inspection history to prioritize casework.
"Show repeat violation properties in Ward 2."

4Public Safety Incident Analytics

Users: Police/fire command staff
Surfaces patterns in calls for service and response times across districts.
"Where have response times increased this quarter?"

5Budget Transparency Portal

Users: Public, council members
Lets the public ask plain-language questions about spending and budgets.
"How much did the city spend on road repair last year?"

6Infrastructure Asset Manager

Users: Public works staff
Tracks maintenance schedules and condition for roads, parks, and facilities.
"Which bridges are due for inspection this year?"

7Legislative Research Assistant

Users: Council staff, clerks
Searches meeting minutes, ordinances, and resolutions by topic or sponsor.
"What ordinances were passed about short-term rentals?"

8Social Services Eligibility Navigator

Users: Caseworkers, residents
Helps determine program eligibility by linking household, income, and case data.
"Is this household eligible for utility assistance?"

9Vendor & Contract Intelligence

Users: Procurement staff
Flags upcoming contract renewals and tracks vendor performance.
"Which contracts expire in the next 60 days?"

10Emergency Resource Coordinator

Users: Emergency management
Correlates shelters, supplies, and incident data during emergency response.
"Which shelters have capacity near the flood zone?"

11Constituent Correspondence Router

Users: Constituent services staff
Automatically classifies and routes resident emails/calls to the right department.
"Route this complaint to the correct department."

12Property & Tax Records Assistant

Users: Residents, assessors
Answers questions about assessed value, tax history, and appeals status.
"Has this property's assessment been appealed?"
